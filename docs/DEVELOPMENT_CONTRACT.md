# Shared implementation contract

The first implementation uses Unix epoch seconds as `i64` for observations, with CLI OAuth expiry retained in milliseconds inside opaque credential JSON. Rust names are snake_case; redacted IPC view types use camelCase. Tokens never enter those view types. All files are owned by one assigned agent. Root owns workspace, provider-claude, desktop Rust bridge, integration, CI, docs and publishing; core_policy owns core/runtime, platform_storage owns platform/diagnostics/scripts, desktop_ui owns the renderer. English is the default language, with Romanian supported through localized UI catalogs and Rust messages.

## Core agent

Own `crates/switcher-core/**`. Export models through `pub use` at crate root:

- `ProviderId` (`Claude`, `Codex`, lowercase serialized, default Claude).
- `StoredAccount`: public fields `id: String`, `provider: ProviderId`, `name: String`, `saved_at: i64`, `oauth_account: serde_json::Value`, `credentials: Value`, and optional/persisted legacy state `refresh_fail_at`, `rate_limited_until`, `expected_weekly_reset_at`, `primed_for_reset_at`, `consecutive_rate_limits: u32`, `last_usage: Option<UsageResponse>`, `last_usage_at`, `last_endpoint_read_at`, `last_endpoint_attempt_at`, `subscription_status: Option<String>`, `subscription_started_at`, `plan_tier: Option<String>`, `profile_checked_at`, `renewal_day: Option<u8>`, `reset_status: Option<ResetStatus>`, `reset_status_at`, `pending_reset_claim: Option<PendingResetClaim>`, `last_reset_outcome: Option<String>`, `last_reset_attempt_at`, `identity_verified: bool`, `priming_pending_for: Option<i64>`. All optional timestamps are `Option<i64>`, sensible Default. Custom Debug redacts credential JSON. Methods `account_uuid`, `organization_uuid`, `email`, `access_token`, `refresh_token`, `expires_at_ms` return borrowed strings / numeric timestamp. Constructor `StoredAccount::new(name, identity, credentials, now)` assigns stable UUID and provider Claude.
- Five-hour priming adds optional `StoredAccount` timestamps `expected_five_hour_reset_at`, `five_hour_primed_for_reset_at`, `five_hour_priming_pending_for` and `five_hour_started_at`. Absent fields default to `None` and are omitted on serialization, preserving older records. The first three track scheduling, skipped/handled resets and reconciliation; the last records an actual successful start, never a skipped or refused attempt. The existing `auto_start_window_enabled` toggle covers both Claude windows.
- `UsageWindow { utilization: f64, resets_at: Option<i64> }`, `UsageLimit {kind:String,group:String,percent:f64,resets_at:Option<i64>,scope:Option<Value>}` (unknown fields retained where useful). `UsageResponse {five_hour,seven_day,seven_day_sonnet:Option<UsageWindow>,extra_usage:Option<Value>,limits:Option<Vec<UsageLimit>>,cedar_ember:Option<ResetStatus>}`. Public methods `weekly_utilization`, `weekly_utilization_for_model(Option<&str>)`, `scoped_limit`, `scoped_weekly_limits`, `weekly_resets_at`, `weekly_all_resets_at`, `weekly_reset_bucket`, `earliest_reset`; method `UsageLimit::label`. API timestamp serde accepts ISO strings, numeric seconds, null; tolerant cedar block/grant parsing.
- `ResetGrant` and `ResetStatus` with source-native snake_case fields, optional timestamps parsed from ISO/seconds; `ResetGrant {id, resets_left:u32, starts_at:Option<i64>, ends_at:Option<i64>, clears:Vec<String>, paused:bool, usable_now:bool, use_requires_limit:bool}`; `ResetStatus {eligible:Option<bool>,ineligible_reason:Option<String>,grants:Vec<ResetGrant>,next_grant_id:Option<String>,cooldown_until:Option<i64>,weekly_resets_at:Option<i64>}`. Omitted requires-limit true, usable-now false. `available(now)` returns live offers.
- `PendingResetClaim {grant_id:String,request_id:String,created_at:i64}`.
- `Settings {poll_interval:u64,threshold:f64,auto_switch_enabled:bool,auto_start_window_enabled:bool,auto_use_resets_enabled:bool,appearance:String,language:String,prefer_soonest_weekly_reset:bool}` defaults 300/95/true/true/true/dark/en/true; the last is not written while true, so older records round-trip unchanged. `candidate_order()` maps it to `CandidateOrder`. `validate()->Result<(),...>` ranges 120..900 step30, 50..100 finite, allowed theme and en/ro. Rust persistence retains snake_case; SettingsView converts to camelCase IPC.
- `AccountUsageInfo {account:StoredAccount,usage:Option<UsageResponse>,is_active:bool}`.
- Pure policy functions `is_usable(info,threshold,model)`, `has_headroom(info,threshold,model,margin)`, `best_candidate(infos,threshold,model,order)->Option<String>` (stable id), `consumption_plan(infos,threshold,model,order)->Vec<String>` with `CandidateOrder {SoonestWeeklyReset (default), MostWeeklyLeft}` and the provider-neutral `CandidateRank`/`compare_candidates` that Codex ranking reuses, `next_poll_delay(interval,active_usage,threshold,model,exhausted)->u64`, `decide_resets(infos,threshold,model,now)->Vec<ResetAction>`; `ResetAction {account_id,grant_id,reason:String,switch_first:bool}`.
- `ResetOutcome` variants `Reset {resets_left:Option<u32>,cooldown_until:Option<i64>}`, `AlreadyUsed`, `NotLimited`, `Cooldown {until:Option<i64>}`, `Ineligible {reason:Option<String>}`, `Unavailable {reason:Option<String>}`, `Transport`, `AuthError`; `is_final`, human-safe `text` methods. `parse_reset_outcome(status:u16,body:&Value)` handles conservative 5xx uncertainty. `apply_reset_outcome(status:&mut Option<ResetStatus>,grant_id:&str,outcome:&ResetOutcome)`.
- `fraction_to_percent`, `usage_from_headers(headers:&BTreeMap<String,String>)->Option<UsageResponse>`, `usage_from_limit_refusal(headers,previous:Option<&UsageResponse>)->Option<UsageResponse>`; caller tracks unknown/freshness separately. `parse_timestamp(&Value)->Option<i64>`.
- `import_legacy(value:&Value,now:i64)->Result<StoredAccount,...>` preserves legacy fields, ISO Date vs numeric epoch state and credentials extensions. `next_renewal(account:&StoredAccount,now:i64)->Option<i64>` uses local calendar.

## Platform agent

Own `crates/switcher-platform/**`; no core dependency required. Export:

- `PlatformError` typed, safe Display (never data). `Result<T>` alias if desired.
- `CliPaths {config_dir:PathBuf,credentials_file:PathBuf,global_config_file:PathBuf,settings_file:PathBuf,context_id:String}`; `discover()->Result<CliPaths>` and `for_home(home:PathBuf)->CliPaths` for fixtures. Handle custom overrides only with evidence, fail closed when ambiguous. `default_model()->Result<Option<String>>` reads only model.
- `Vault::open(directory:PathBuf)->Result<Vault>` production OS-protected master key, encrypted AEAD account/journal files and restrictive permissions. `Vault::with_key(directory,key:[u8;32])->Result<Vault>` explicitly fixture injected. `load<T:DeserializeOwned>(&self,name:&str)->Result<Option<T>>`, `save<T:Serialize>(&self,name:&str,value:&T)->Result<()>`, `remove(&self,name:&str)->Result<()>`. `app_data_dir()->Result<PathBuf>`.
- `ActiveStore::new(paths:CliPaths)->Self` (default OS backend), `ActiveStore::file(paths)->Self` (fixture/file override). Public `paths` or `paths()` accessor. `read()->Result<ActiveSnapshot>`, `switch(&self,credentials:&Value,identity:&Value,vault:&Vault)->Result<()>`, `recover(&self,vault:&Vault)->Result<Recovery>` (`Clean`, `Completed`, `RolledBack`, or `SetAside` when another writer owns the login and the journal was retained under a new encrypted name).
- `ActiveSnapshot {credentials:Value,identity:Value, fingerprint:String, identity_fingerprint:String}` with redacted Debug. `fingerprint` covers only the claudeAiOauth blob and the oauthAccount owner (account + organization UUID); `identity_fingerprint` covers only the owner. Missing active login gives null identity/empty credentials; corrupt files error. `switch` patches only claudeAiOauth/oauthAccount into the files as they are at write time, encrypted journal, first backup, native replacement, contextual lock and conditional recovery after external changes. Atomic storage operations must preserve unknown fields and permissions. Mac Keychain item/fallback adapter in cfg, Linux active file/vault Secret Service with explicit errors; native platform evidence separately tracked.

## UI agent

Own `apps/desktop` EXCEPT `apps/desktop/src-tauri/**` (root). Svelte 5 + TS/Vite, npm lockfile. Runtime bridge is `@tauri-apps/api/core` invoke + event listen. Native window, full English/Romanian localization and approved image-model visual design. Codex future capability only, no fake support.

IPC `Snapshot` camelCase:
`{revision:number,provider:'claude',accounts:AccountView[],activeId:string|null,activeModel:string|null,settings:Settings,lastRefreshAt:number|null,busy:boolean,error:ErrorView|null,notice:ErrorView|null,demo:boolean,consumptionPlan:string[]}`.
`ErrorView={code:string,accountId:string|null,param:string|null,action:'autoSwitch'|null,at:number}`: `code` is a renderer catalog key (never provider or file text), `param` only a fixed environment-variable or settings name; `notice` persists for the session until the window dismisses it.
`AccountView={id,name,email,provider,active,isNext,exhausted,identityVerified,usage:UsageView|null,usageAt:number|null,scopedAt:number|null,decisionFresh:boolean,error:string|null,signInRequired:boolean,freesAt:number|null,subscriptionStatus:string|null,planTier:string|null,renewalDay:number|null,nextRenewalAt:number|null,resets:ResetView,primedAt:number|null,fiveHourPrimedAt:number|null}` (`error` is a catalog code; `freesAt` is when an exhausted account's blocking windows reopen; `fiveHourPrimedAt` records the last successful 5-hour start).
`UsageView={fiveHour:{utilization,resetsAt:number|null},sevenDay:{utilization,resetsAt:number|null},weeklyOverall:number,weeklyModel:number,weeklyOverallResetsAt:number|null,weeklyModelResetsAt:number|null,scopedLimits:{label,percent,resetsAt:number|null}[]}`.
`ResetView={available:number|null,expiresAt:number|null,cooldownUntil:number|null,pending:boolean,lastOutcome:string|null}`.
Settings has camelCase `pollInterval,threshold,autoSwitchEnabled,autoStartWindowEnabled,autoUseResetsEnabled,appearance,language,preferSoonestWeeklyReset`.

Commands: `get_snapshot`, `refresh_all`, `refresh_account({id})`, `switch_account({id})`, `delete_account({id})`, `set_renewal_day({id,day:number|null})`, `update_settings({settings})`, `import_current`, `begin_login` returns `{id,url}`, `finish_login({id,code})`, `cancel_login({id})`, `preview_legacy_import` native folder returns `{id,valid:number,invalid:number,names:string[]}|null`, `apply_legacy_import({previewId})`. Mutations return updated Snapshot except login/preview; safe error strings on rejection. Rust opens authorization URL externally. Listen `snapshot_changed`, fallback pure snapshot polling does no provider network. UI code never reads arbitrary files or shell.

## Coordination

Codex manual resets (owner request, 2026-10-09) add `codex_consume_reset({id})` and `CodexAccountView.reset={pending,lastOutcome,usable}`. `lastOutcome` is `reset|alreadyRedeemed|nothingToReset|noCredit|null`; `usable` is a native capability. The encrypted saved account adds optional, omission-preserving `pending_reset_key` and `last_reset_outcome`; keys and raw detail rows never cross IPC. Persist the key before consume, verify current backend workspace ownership, reuse unresolved keys across restart even at zero credits, and fetch usage after consumption. Polling never redeems resets. Pending accounts cannot be deleted. Older Codex records keep format 1 and load unchanged.

Codex quota observations add optional, omission-preserving `resetCreditDetails: {expiresAt:number|null}[]|null` for available Codex reset credits. Native projection filters redeemed/unknown-type rows and invalid dates, deduplicates private IDs and sorts known dates first; only Unix seconds in 0..253402300799 or explicit no-expiry null reach IPC. Missing/empty details never imply no expiry or alter the authoritative count. The UI groups matching expiries, formats a full local date/time with timezone, and labels partial coverage. Older quota records deserialize without this field and retain their serialized shape.

Default validation is fixture-only. The original source is preserved in a separate private checkout; this public tree contains sanitized design documentation and new code. No subagent publishes, touches real auth files, or modifies the original source. Root performs workspace/network/build/publish actions. Run crate-local tests and report results; notify root before shared dependency changes. Root runs integration and native packaging. The owner selected Direction A in docs/design/PROPOSALS.md. New installations default to dark; explicit saved appearance preferences are preserved.
