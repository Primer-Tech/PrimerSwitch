# Shared implementation contract

## Account automation update (2026-10-15)

The owner authorized implementation, local reinstall and a push to main after validation. Existing `Settings.threshold` remains the legacy fallback. New optional, omission-preserving `claude_threshold` and `codex_threshold` fields have `Settings::threshold_for(ProviderId)` as the authority; new renderer controls save both explicit provider defaults together so editing one never changes the other.

Core exports `AccountAutomation {enabled:bool,threshold:Option<f64>,priority:Option<u16>,return_on_five_hour_reset:bool}`. Default is true/None/None/false. Validate finite thresholds 50..=100 and priorities 1..=99; lower priority numbers come first. `effective_threshold(default)` resolves the account override. Saved Claude and Codex accounts add `automation` omitted when default and optional `preferred_return_reset_at` tracking an observed spent five-hour window. Native persistence retains snake_case. Runtime exports camelCase `AccountAutomationView` with the same four fields and conversions; both account snapshots add `automation` and `effectiveThreshold`. Both provider snapshots add nullable `returnHoldUntil`.

Claude commands: `update_account_automation({id,automation:AccountAutomationView})` and `resume_automatic_returns`. Codex equivalents: `codex_update_account_automation({id,automation})` and `codex_resume_automatic_returns`. Renderer mutation returns the corresponding provider snapshot. Backend remains authoritative. Preference edits do not require real provider calls and must preserve unrelated state.

Excluded accounts cannot be automatic destinations, including Claude last-resort reset switches. Each candidate uses its own effective threshold for eligibility and headroom, and all displayed meters/alerts/next-account reasons use that same threshold. Add optional `priority` to `CandidateRank`; preserve preferred headroom first, then explicit ascending priority (None last), then the existing weekly-order comparator and stable tie breakers. With default account preferences, existing ranking stays unchanged.

An automatic return requires auto-switching on, an opted-in higher-priority inactive account, a previously observed spent five-hour window whose reset passed, fresh identity/usage revalidation, preferred headroom in every applicable reported binding window, and no operation/manual hold/cooldown. Missing windows/timestamps never imply free quota. Return markers, manual holds and cooldowns persist; manual selection pauses returns for 15 minutes, with an explicit resume control. An active recovered preferred account handles its old marker without another switch. One successful return handles that reset so it cannot repeatedly pull the user back. Recovery checks should become due around known reset times, respect retry floors and avoid a polling loop. Natural recovery is separate from priming or spending reset credits. Automatic switching/return must reuse the existing transactional provider paths.

The observed five-hour window arms at the account's effective switch threshold, rather than requiring 100% usage: ordinary rotation usually happens before 100%. A fresh post-reset explicit zero-usage five-hour window may have no new reset date because it is unused/unstarted; that is valid recovery evidence when the old observed reset is known and passed. An entirely absent five-hour window cannot establish recovery, and a nonzero window with an unknown new reset remains ineligible. Fresh known weekly headroom does not require a weekly reset date. Consuming a banked reset handles the natural-return marker instead of impersonating a natural reset.

## Core agent

Own `crates/switcher-core/**`. Export models through `pub use` at crate root:

- `ProviderId` (`Claude`, `Codex`, lowercase serialized, default Claude).
- `StoredAccount`: public fields `id: String`, `provider: ProviderId`, `name: String`, `saved_at: i64`, `oauth_account: serde_json::Value`, `credentials: Value`, and optional/persisted legacy state `refresh_fail_at`, `rate_limited_until`, `expected_weekly_reset_at`, `primed_for_reset_at`, `consecutive_rate_limits: u32`, `last_usage: Option<UsageResponse>`, `last_usage_at`, `last_endpoint_read_at`, `last_endpoint_attempt_at`, `subscription_status: Option<String>`, `subscription_started_at`, `plan_tier: Option<String>`, `profile_checked_at`, `renewal_day: Option<u8>`, `reset_status: Option<ResetStatus>`, `reset_status_at`, `pending_reset_claim: Option<PendingResetClaim>`, `last_reset_outcome: Option<String>`, `last_reset_attempt_at`, `identity_verified: bool`, `priming_pending_for: Option<i64>`. Methods `account_uuid`, `organization_uuid`, `email`, `access_token`, `refresh_token`, `expires_at_ms` return borrowed strings / numeric timestamp. Constructor `StoredAccount::new(name, identity, credentials, now)` assigns stable UUID and provider Claude.
- Five-hour priming adds optional `StoredAccount` timestamps `expected_five_hour_reset_at`, `five_hour_primed_for_reset_at`, `five_hour_priming_pending_for` and `five_hour_started_at`. - `UsageWindow { utilization: f64, resets_at: Option<i64> }`, `UsageLimit {kind:String,group:String,percent:f64,resets_at:Option<i64>,scope:Option<Value>}` (unknown fields retained where useful). `UsageResponse {five_hour,seven_day,seven_day_sonnet:Option<UsageWindow>,extra_usage:Option<Value>,limits:Option<Vec<UsageLimit>>,cedar_ember:Option<ResetStatus>}`. ## Platform agent

Public `paths` or `paths()` accessor. `read()->Result<ActiveSnapshot>`, `switch(&self,credentials:&Value,identity:&Value,vault:&Vault)->Result<()>`, `recover(&self,vault:&Vault)->Result<Recovery>` (`Clean`, `Completed`, `RolledBack`, or `SetAside` when another writer owns the login and the journal was retained under a new encrypted name).
- `ActiveSnapshot {credentials:Value,identity:Value, fingerprint:String, identity_fingerprint:String}` with redacted Debug. `fingerprint` covers only the claudeAiOauth blob and the oauthAccount owner (account + organization UUID); `identity_fingerprint` covers only the owner. Missing active login gives null identity/empty credentials; corrupt files error. `switch` patches only claudeAiOauth/oauthAccount into the files as they are at write time, encrypted journal, first backup, native replacement, contextual lock and conditional recovery after external changes.
